# Standalone content-bank builder: subscription backend, references, anti-padding gate

- **Date:** 2026-07-21 (session began 2026-07-20)
- **Branch / commits:** `main`; three PRs merged — **#18** (standalone builder + adversarial review + subscription backend + `--model` + inline references, closes #16), **#20** (anti-padding gate, closes #19). Issue **#19** opened then closed via #20. Final `main` tip `1b0513a`.
- **Summary:** Built issue #16's standalone Python content-bank builder end-to-end, then followed the evidence: added an adversarial-review step, a subscription-billed Claude backend, a per-run model override, inline leader references, and a deterministic anti-padding gate — each decision driven by measured Philippians builds rather than assumption.

## Request
Starting from "issue #16 is ready to build, how to proceed?", the session grew through a sequence of user directives: get #16 done, add an adversarial review step, build Philippians with the Python script and compare quality against the Claude Code build; then route the builder to the subscription (strong model); then audit the pipeline for completeness (were references/sections/arc all generated?); then evaluate `deepseek-v4-pro`; then build an anti-padding gate — with the user explicitly demanding verification before trusting a "brief-aware" heuristic on a cheap model.

## What we did
- **Issue #16 — standalone builder (PR #18).** Spec + plan under `docs/superpowers/`, then TDD: committed `gates.py` (`quote_check`, `schema_check`, new `refs_in_range` catching the MAT-035 scope-drift class), self-contained section prompt, `build_cli.py` orchestrator (manifest walk, backoff, per-unit isolation), and `review.py` (optional two-lens adversarial + revise). LLM only via the existing `content_bank.author.llm.llm()` seam → `llm_core` (deepseek-v4-flash). The stdlib-vs-SDK open question was recorded as moot (llm_core already vendored).
- **PHP comparison.** Built all 14 PHP units with `--review` on deepseek-flash (~$0.41, 0 failures, 0 gate defects). Finding: flash **pads dimensions the passage doesn't support** (D2 sequence 38 vs the Claude workflow's 7 on an epistle) — a model-judgment gap the gates can't see.
- **Subscription backend.** De-risked `claude -p` empirically: works headless and nested, but `--bare` breaks subscription auth (drops the credential source), and the prompt must go on stdin. Added a second `llm()` backend (`--backend claude`) shelling to `claude -p --model opus`, billing the subscription (no `ANTHROPIC_API_KEY` in env ⇒ OAuth login). **Proof:** same pipeline + Opus collapsed padding on PHP-002 (31→16 items, D2 7→2) to workflow parity — confirming the pipeline was never the limiter, the cheap model was.
- **Pipeline audit → inline references.** Traced four generation stages; found leader references (answer keys / leader notes) were **not generated** — the old Workflow JS layered those instructions on top of the pack and the standalone builder lost them (0/31 flash, 0/16 Opus vs 16/18 workflow). Fixed by requesting inline `leader_reference` in `build_draft_prompt`, single-sourced from `rubric.reference_criteria()`. Re-verified on PHP-003 (Opus): 13/15 items carry correct references. Confirmed "arc" = the section layer; no unit above `section`.
- **`--model` override + deepseek-v4-pro eval.** Added `--model` (env-var pattern like `--backend`). Pro does **not** fix over-generation: still 31 items (padding just redistributed, D2 7→4 but D7→6), at **$1.03 and 6.7 min/unit** — Opus-tier cost without Opus discipline. No slot between flash and Opus.
- **Anti-padding gate (PR #20), with verification first.** The user challenged the planned "brief-aware" signal: a cheap model that pads the draft will also mis-declare supported dimensions. Verified — flash on PHP-002 (5 samples) reliably down-rated D2 but rated D1/D5/D6 `primary` where Opus said `incidental`; the ceiling just moves draft→brief. **Dropped brief-aware.** Built two model-independent gates instead: `thread_span_check` (hard — thread on a single-pericope section) and `dimension_cap_check` (soft — over `--dim-cap`, default 3; feeds the repair loop then logs, never hard-fails). Effectiveness: flash PHP-002 31→21 items, max/dim 7→4 toward workflow shape.
- **Process fixes.** Restored committed PHP briefs the builder overwrote (ran without `--briefs-dir`); moved two commits accidentally made on local `main` to `feature/anti-padding-gate` before pushing; updated PR #18's body via the REST API after `gh pr edit`'s GraphQL path hit a projects-classic deprecation error.

## Outcome
All merged to `main`; 174 content_bank + 4 llm_core tests green (the `[FAIL] MAT-035` line in output is a per-unit-isolation test's expected log, not a failure). The builder now: runs the deterministic pipeline via a swappable `llm()` seam; supports `--backend {llm_core,claude}`, `--model`, `--review`, and `--dim-cap`; generates briefs, pericope items, section/arc content, and inline leader references; and gates on quote + schema + ref-range + thread-span (hard) with soft anti-padding. Empirical bottom line: the drafting model is the quality ceiling — flash for cheap bulk, Opus-via-subscription for parity; pro and cheap-model "brief-aware" don't earn their cost; the deterministic cap closes part of the gap model-independently.
